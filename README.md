# Router Loot

Мод для R.E.P.O., который добавляет роутеры в список ценных предметов.

[https://thunderstore.io/c/repo/p/romanvht/RouterLoot/](https://thunderstore.io/c/repo/p/romanvht/RouterLoot/)

## Установка

Нужны R.E.P.O., BepInEx 5 и REPOLib 4.2.0.

Импортируйте `RouterLoot-*.zip` в менеджере модов или скопируйте `RouterLoot.dll`
в папку `BepInEx/plugins` игрового профиля.

## Настройки в игре

После первого запуска появится файл `BepInEx/config/romanvht.RouterLoot.cfg`.
У каждой модели есть свой раздел с параметрами `ValueMin`, `ValueMax`, `Mass` и `Fragility`:
минимальная и максимальная базовая стоимость, масса и хрупкость от 0 до 100.

Начальные цены и масса берутся из `assets/catalog.json`; начальная хрупкость - 55.

Для проверки включите `Debug → EnableSpawnKey`. Хост сможет нажать **F8** во время уровня,
чтобы создать набор роутеров перед собой.

## Добавление своей модели

1. Подготовьте статическую модель в формате **GLB** с текстурами внутри файла.
2. Положите её в `assets/models`, например `assets/models/my_router.glb`.
3. Запустите сборку.
4. Установите мод.

В имени используйте латинские буквы, цифры, `_` и `-`. Имена должны быть уникальными без учёта регистра;
OBJ и FBX перед добавлением нужно преобразовать в GLB любым подходящим редактором или конвертером.

Новая модель получает имя файла как название, стоимость 500–1000, массу 1 и ширину 0.42 метра.
Пропорции сохраняются. Модель центрируется по горизонтали, а её нижняя точка ставится на землю.
При замене GLB настройки существующей модели сохраняются. При удалении файла его запись
удаляется из каталога во время следующего импорта.

## Размеры и коллайдеры

Настройки моделей находятся в `assets/catalog.json`:

| Поле | Назначение |
| --- | --- |
| `id` | Имя GLB без расширения |
| `name` | Название предмета |
| `min`, `max` | Начальная стоимость |
| `mass` | Начальная масса |
| `width` | Ширина модели в метрах; по умолчанию 0.42 |
| `autoColliders` | Автоматически рассчитывать коробку столкновения |
| `colliders` | Ручные или рассчитанные коробки столкновения |

При `autoColliders: true` коробка пересчитывается после изменения модели или ширины.
Для более точных столкновений задайте несколько коробок вручную и установите `autoColliders: false`.
Если поле отсутствует, ручные коробки также сохраняются.

Каждая коробка содержит `center: [x, y, z]` и `size: [x, y, z]` в метрах относительно
уже масштабированной модели. Коробки должны охватывать всю геометрию;
сборка сообщит об ошибке, если после замены модели они перестали её покрывать.

## Требования к GLB

Используйте самодостаточный GLB 2.0: геометрия и текстуры должны находиться внутри файла.
Модель должна быть статической, с непрозрачными материалами, без анимации, скелета и morph targets.
Все размеры после масштабирования должны быть больше нуля и не превышать 2 метра.

Поддерживаются несколько частей и материалов, вложенные трансформации, нормали, UV,
двусторонние поверхности, цвет и текстура основного материала в PNG/JPEG.
Если нормалей нет, импортёр создаёт их по граням.
Металличность и шероховатость берутся из числовых параметров материала;
дополнительные карты, например normal map, не используются.

На одну часть допускается до 150000 развёрнутых вершин, включая обратные стороны двусторонних поверхностей.
Допустимые обязательные расширения GLB - `KHR_mesh_quantization` и `KHR_texture_transform`.
Сжатие Draco, meshopt и текстуры KTX2/BasisU не поддерживаются.

## Сборка из исходников

Нужны .NET SDK 9, PowerShell, установленная игра и профиль с BepInEx и REPOLib.
При первой сборке NuGet загружает библиотеку SharpGLTF для импортёра.
Python, Node.js, Blender и Unity Editor для сборки не нужны.

Откройте PowerShell в папке проекта и укажите пути к игре и профилю:

```powershell
.\scripts\build.ps1 `
    -GameDir 'D:\SteamLibrary\steamapps\common\REPO' `
    -ProfileDir 'C:\path\to\profile'
```

Скрипт копирует библиотеки из профиля в `.deps`, импортирует GLB и собирает мод.
Чтобы повторно использовать скопированные библиотеки:

```powershell
.\scripts\build.ps1 -GameDir 'D:\SteamLibrary\steamapps\common\REPO' -UseLocalDependencies
```

Готовые `RouterLoot.dll` и `RouterLoot-*.zip` появятся в `dist`.
Ключ `-NoPackage` пропускает создание ZIP.

Импорт без сборки игрового плагина:

```powershell
dotnet run --project asset-tool/AssetTool.csproj -- assets obj/manual/runtime-assets
```

## Проверка кода и ассетов

```powershell
dotnet run --project tests/AssetChecks.csproj
```

Проверка контролируют геометрию, UV, материалы, каталог и коллайдеры, добавление, изменение и удаление моделей, обработку ошибок импорта.
